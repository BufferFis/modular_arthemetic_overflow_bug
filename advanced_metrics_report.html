Comprehensive Vulnerability Analysis Report

1. C uint8 Overflow (Shopping Cart)

Mechanism: A multiplication operation on 8-bit unsigned integers causes values exceeding 255 to wrap around to low values (e.g., 200 * 2 = 400 = 144 modulo 256).

Exploit: Attackers intentionally order high quantities so the total price overflows into a small value, bypassing the bank balance check.

Fix: size_t was implemented to calculate the true cost with bounds checking prior to execution.

2. Java int32 Overflow

Mechanism: Standard 32-bit signed integers in Java wrap into negative values when exceeding 2,147,483,647.

Exploit: Very large quantity attacks force the total cost into negative values, tricking the "is cost < balance" logic and crediting instead of deducting the attacker.

Fix: Shifted to BigInteger APIs ensuring theoretically infinite precision memory allocation during calculations.

3. Improper BigInteger Migration

Mechanism: Using .intValue() at the very end of a BigInteger workflow immediately squashes the safely calculated number back into a 32-bit space.

Exploit: Exploited exactly like a standard Java int32 overflow; the math was safe, but the storage cast broke the boundaries.

Fix: Replace type-casting with .compareTo() logic to natively keep validation strictly within the BigInteger class.

4. Nuclear Gandhi (8-bit Underflow)

Mechanism: Unsigned integer underflow triggers when subtraction falls below 0, wrapping strictly around to 255.

Exploit: Starting with a peaceful value of 4, applying a democracy discount forces underflow. The result wraps backwards, granting Gandhi a highly aggresive nuclear maglomanian score of 250+.

Fix: Simple conditional boundaries checking if (gandhi >= modifier) before modifying.

5. Modular Reduction (Montgomery/Barrett)

Mechanism: Intermediate truncation flaws or incorrect approximation bounds skipping final mathematical loops.

Exploit: Attacker introduces specific lengths to systematically avoid the necessary while-loop correction in Barrett reduction, or truncates precision registers in Montgomery.

Fix: Correct recursive loop implementations strictly bounded to mathematical theorem specs instead of hardware optimisations.
